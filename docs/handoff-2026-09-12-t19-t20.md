## 2. #27(T19)交付了什么:一段 playbook section

现在系统提示里多一段 `galfree-workflow`(order 4900),内容 = 七环的顺序 / 每环的闸门 /
完成判据 / 谁来做 / 怎么问现状 / 如实呈现的纪律。

**两条设计上的硬选择(改之前先读契约的 T19 节)**:

1. **判据写成"板上的字段路径"**(`summary.missingSlots` / `playtest.state`…),闸门写成

   指引里**没有**会过期的数字("8 个槽"这种)。
2. **工具面只报真的注册了的入口**:每一步挂一组工具名,渲染时现问 `ctx.tools.get(name)`。

## 4. #29(T21)交付了什么:板上的「下一步」

`progress.nextActions[]` —— 纯推导的行动清单(带 `actor` 与跳转 `target`),回答"接着做什么"
(`problems` 回答"哪里坏了")。顺序固定(阻塞在前、打磨在后);板上没毛病时给一条
`publish-ready` 而不是空数组。**两个面读同一份**:面板舞台板最上面那行「下一步」(带
human/agent 徽标 + 可点跳转)、以及 `galfree_project_status` 带回的同一份(工具描述里明说别自己推)。

两个坑值得记住(都是审查逼出来的):
1. 上一次构建**失败**时账本里 `ok:false` 且 `stale:false` —— 不单独判 `ok` 就会对着**零产物**
   说"产物就是当前这一版"。现在推的是 `publish-failed`(detail 带日志尾巴);
2. 发布那句措辞要准:它推的是"**挡着发布的东西都没了**",不是"板上齐了"(同一行里可能还有
   "请人盖戳"),而 SDK/输出目录/界面图那些前置**不在这份推导里**(那是 `publishReadiness()` 的事)。

## 5. 本会话踩过的四个坑(都值得记住)

1. **别用 PowerShell 改源码。** 我为了批量替换一个参数,用了
   `(Get-Content -Raw) -replace ... | Set-Content`,它按**系统 ANSI 代码页**读写,
   把一个测试文件的中文与换行一起搞坏(解码时把多字节字符的尾巴和紧随的换行配成一对,
   行边界都丢了),**不可恢复**,只能整个重写。改文件一律用 `edit` / `write` 工具。
   同一天我又用 `edit` 手滑把 `readBible` 的 `join(root, BIBLE_FILE)` 改成 `join(BIBLE_FILE)`
   —— 于是它去 **CWD** 读设定集,一路"读到空文档"却谁都不报错,直到 T21 的守卫红。
   **改一行也要立刻跑那个文件的测试**,别攒着。
2. **同义反复的守卫**:给"发布那道闸门"写守卫时,我构造的坏局面顺手弄出了 lint 错,
   于是"反正有东西拦住了"它就绿 —— 把发布前置里的音频检查拆掉它照样绿。
   收紧成"只坏一处 + 断言拦住它的**就是**那一条"之后才真的能红。
   **端点守卫要验红,而且要验它红在你要它红的那一点上。**
3. **跑慢带要设 `GALFREE_SDK_DIR`。** 不设的话 `sdk.slow.test.ts` 会往临时目录**下载 155MB**,
   5 条用例各 600 秒超时(我第一次就是这么白等了 50 分钟,还一度以为是回归)。
   本机的钉版 SDK 在 `~/.dsh/dsh-galfree/sdk`:

   ```powershell
   $env:GALFREE_SDK_DIR="$env:USERPROFILE\.dsh\dsh-galfree\sdk"; npm run test:slow
   ```

   另外:**跑慢带时别同时跑别的 vitest 进程**(仓库里记过这条,我犯过一次)。

4. **preset 里的插件行是 cordis 插件:服务不能"随手取"。** galgame preset 那个前置检查行第一版
   没声明 `inject`,用户一切换就报
   `failed to apply loader entry galfree-guard (./guard.mjs): cannot get property "tools" without inject`
   —— 修法就是 `export const inject = ['tools']`(已有一条守卫盯着它)。
   顺带记住:preset 这一层**只有真机能验**(roster 的健康检查只看"模块能不能解析"),

## 7. T24(#32)—— `galfree_playtest` 卡住:已修(2026-09-12,同一会话)

**结论先给**:那是个**形状问题**,不是偶发 bug。工具体在 `await playtestStart(...)` 上
**同步等游戏窗口被关掉**,而"退出"要人去点那个窗口 —— 同时它**没观察 `exec.signal`**
(宿主的取消是协作式的:每个工具体必须自己看),于是"取消这一轮"也不会让它停,
而缺省上限是 **15 分钟**;面板运行中只有一个 `disabled` 的按钮。

**开红的路子**(这一段是给下一个"用户说卡住"的人的):先把**夹具的 spawn 写成永不退出**
(那正是"人没关窗口"的形状),再断言"工具必须立刻回来" —— 修之前它真的会挂到测试自己的
超时,红的形状与用户看到的一模一样。别先去读代码。

**修了什么**(机制与决定写在契约的「试玩不会把人绊住(T24 / #32 之后追加)」节,这里只记要点):

1. `PlaytestPorts.spawn` 多接一个 `signal`;`exec.signal` 从工具面一路传到子进程
   (`spawnWithLog` 里 `child.kill()`)。**被取消的那一次不进账本** —— 它不是一次试玩;
2. 缺省等待 **15 分钟 → 3 分钟**(产品决定:人总是要亲手关窗口),工具面可给
   `timeout_seconds`(封顶 15 分钟)。停下来的**原因与时长**进结果:
   `{timedOut, aborted, killed, elapsedMs}` → `PlaytestRun` → `progress.playtest` → 板上的字;
3. 面板能取消:`POST /playtest/cancel` → `cancelPlaytest()`,与宿主中断**同一个信号**;
   `progress.playtestRunning`(运行时事实,不是推导)让**agent 起的试玩**也看得见、也停得掉;
4. 工具描述如实写明"**这条命令会等 —— 等的是人去把那个游戏窗口关掉**",并给出分钟数
   (与常量同源:守卫断言描述里真有那个数)。

**没做的**:票面方向 3 那条"提交 → 拿句柄 → 之后再查"的后台队列(要动接缝,是独立一张票)。

**双轴审查逼出来的五处**(值得下一个人记住:这两条都是"上报的结论与事实不符",正是这张票的病根):

1. 契约写了"断开那次 HTTP 也算取消",代码里**没有**这件事 → 改成"显式路由是主路,
   断开只当兜底",并在注释里写明为什么兜底不能当契约(实测 undici 把 fetch 的 abort
   收在自己那侧,服务端那个 socket 不一定关);
2. 我在**写测试时才发现**的:`res.on('close')` 不能白写一条测试就完事 —— 那条测试红了,
   于是结论是"能力没有",不是"测试写错了";
3. `spawn-log.ts` 取消后立刻 resolve,却对外说"进程已杀掉" → 加 `KILL_GRACE_MS` 宽限窗口与
   `killed` 回执,工具/面板/板三处照实措辞("没停就别说停了");
4. `#playtestAbort` 写在 `await previous` 之前 → 排队中的调用会被说成"在跑";排队期间取消
   也无效(会白等前一个) → 占位改到排到队之后 + 排队期间与取消赛跑;
5. 超时被推导成"有报错 · 退出码 -1"、下一步还发"照 traceback 修完再跑" —— 超时是**窗口没关**,
   不是剧本报错 → 板上文字与 `nextActions`(`playtest-timed-out`,actor = human)都分流。

**一个非直觉的实测事实**:Windows 上 `child.kill()` 是**同步**的 —— `close` 紧接着来,
`child.exitCode` 也会被同步设上。所以不能拿 `exitCode` 判"退没退"(那会把超时/取消的原因
丢掉,第一版就是这么错的:回报成"正常退出 code 0")。"为什么停"由发起方记着(`stopReason`),
"退没退"由 `close` 回答。

1. **参考链在用户的图像渠道上不可用**(上游只要公网 URL)—— 要真让它生效,缺的是"公网可取的地址"
   那一环(上游文件上传接口 / 用户图床),属独立一张票;
2. 用户项目 `hjm`(旧模板)缺 `build.name` 与界面补丁里那两行 `build.classify`,发布会被如实拦下;
3. 快带里那条**偶发**失败(`async-image.test.ts` 的「同步适配器遇到异步上游」在机器忙时报
   `fetch failed`,而用例期望的是"指向 async-task")—— 与本轮改动无关,但值得单独修。
