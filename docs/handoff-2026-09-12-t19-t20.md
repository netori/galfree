## 4. 本会话踩过的三个坑(都值得记住)

1. **别用 PowerShell 改源码。** 我为了批量替换一个参数,用了
   `(Get-Content -Raw) -replace ... | Set-Content`,它按**系统 ANSI 代码页**读写,
   把一个测试文件的中文与换行一起搞坏(解码时把多字节字符的尾巴和紧随的换行配成一对,
   行边界都丢了),**不可恢复**,只能整个重写。改文件一律用 `edit` / `write` 工具。
   同一天我又用 `edit` 手滑把 `readBible` 的 `join(root, BIBLE_FILE)` 改成 `join(BIBLE_FILE)`
   —— 于是它去 **CWD** 读设定集,一路"读到空文档"却谁都不报错,直到 T21 的守卫红。
   **改一行也要立刻跑那个文件的测试**,别攒着。
2. **同义反复的守卫**:给"发布那道闸门"写守卫时,我构造的坏局面顺手弄出了 lint 错,
   于是"反正有东西拦住了"它就绿 —— 把发布前置里的音频检查拆掉它照样绿。
   收紧成"只坏一处 + 断言拦住它的**就是**那一条"之后才真的能红。
   **端点守卫要验红,而且要验它红在你要它红的那一点上。**
3. **跑慢带要设 `GALFREE_SDK_DIR`。** 不设的话 `sdk.slow.test.ts` 会往临时目录**下载 155MB**,
   5 条用例各 600 秒超时(我第一次就是这么白等了 50 分钟,还一度以为是回归)。
   本机的钉版 SDK 在 `~/.dsh/dsh-galfree/sdk`:

   ```powershell
   $env:GALFREE_SDK_DIR="$env:USERPROFILE\.dsh\dsh-galfree\sdk"; npm run test:slow
   ```

   另外:**跑慢带时别同时跑别的 vitest 进程**(仓库里记过这条,我犯过一次)。
