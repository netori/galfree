# 配音选型调研:一个中文 galgame 的语音该怎么做(2026-09-14)

> 起点是发起人的一句「TTS 那个我想不到该用什么」。
> 本文件只回答一件事:**《雨停之前》这部戏,5 个角色、上千句台词,用什么做语音、
> 怎么开始**。已有的本机 IndexTTS 事实见 `docs/research-indextts-voice.md`(不重复)。

## 1. 结论(五句以内,能落地)

1. **成本不是决策因素**:整部戏要配的部分(约 1.37 万字符)在任何一家云 TTS 上都是
   **¥3–5**;本地合成是 ¥0。别按"省钱"选型。
2. **真正的卡点只有一个**:IndexTTS **变不出音色** —— 它只能克隆你给的参考音频,
   而你现在**手里一段角色声音都没有**(本机 `voices/` 里只有一个 `测试参考音频.mp3`)。
3. **解法是"声音设计(voice design)"**:用**中文文字描述**凭空造出一个音色,
   而且**它会返回一段预览音频**—— 那段音频就正好是 IndexTTS 需要的参考音频。
4. **推荐路线(零新代码、今天就能跑)**:用百炼"声音设计"造 3–4 个角色音色(一次性
   ¥0–1)→ 存成 `voices/<角色id>.wav` → `galfree_voice_anchor` 登记 →
   `galfree_voice_batch` 导出清单 → **本机 IndexTTS 免费批量** → 导回。
5. **一条叙事事实决定了配音范围**:夏晚**设定上不能有语音**(选择性失语,台词是笔记本上的字)
   —— 给她配音是叙事错误,不是省事。

## 2. 你这部到底要配多少(从登记簿 + 剧本读出来的)

`before_the_rain`:53 场戏,剧本对白 **3,115 行**。按说话人拆开:

| 角色 | 行数 | 要不要配音 | 依据 |
|---|---|---|---|
| `su_qing` 苏晴 | **450** | ✅ 要 | 女主 B |
| `chen_yu` 陈屿 | **414** | ⚠️ **设计决定** | 登记簿:`主角兼视点` —— galgame 的主角通常不配音(玩家代入),但这条由你拍板 |
| `xia_wan` 夏晚 | **207** | ❌ **不能配** | 登记簿:`她不说话 —— 台词以笔记本上的字呈现,所以本作不需要语音`;她患选择性失语 |
| `zhou_yang` 周洋 | **57** | ✅ 要 | 配角(男主朋友) |
| `su_yang` 苏阳 | **29** | ✅ 要 | 配角(苏晴的弟弟,8 岁) |
| (旁白) | 1,958 | — | 叙述,不配音 |

**所以要造的音色是 3 个(最少)到 4 个(连主角一起配)**:
`su_qing`(女 · 17)、`zhou_yang`(男 · 17)、`su_yang`(男童 · 8),外加可选的 `chen_yu`(男 · 17)。

> 顺带一条对工作台有用的:**夏晚那 207 行不该进语音清单**。
> 现在 `galfree_voice_batch` 是按"谁说了话"派生的,她还挂着 `xia_wan` 这个说话人,
> 所以清单里会出现她的 207 行。这是**设定与清单口径之间的一个缺口**——
> 要么给她一个"不配音"的登记位,要么在导出时能按角色排除。见 §8。

## 3. 成本算过了:不是决策因素

只算真人的角色台词(1,157 行 = **13,680 字符**):

| 方案 | 单价 | 整部戏 |
|---|---|---|
| MiniMax `speech-2.8-hd`(同步 T2A) | 3.5 元/万字符 | **≈ ¥4.79** |
| MiniMax `speech-2.8-turbo` / `2.6-turbo` | 2 元/万字符 | ≈ ¥2.74 |
| 豆包语音(火山)低档 | 2.8 元/万字符 | ≈ ¥3.83 |
| Fish Audio | $15 / 百万 UTF-8 字节 | **≈ $0.62**(中文约 3 字节/字) |
| **本机 IndexTTS 2.5** | ¥0 | **¥0** |

只配 3 个配角(536 行)还要再除以二。
**结论:哪怕全配、用最贵的一家,也就一杯饮料钱。** 所以选型该看的是
**音色从哪来**、**一致性怎么保**、**流程顺不顺**,不是单价。

## 4. 真正的卡点:IndexTTS 变不出音色

`docs/research-indextts-voice.md` §3/§5 已经坐实:IndexTTS 2.5
**没有 voice design**(官方 README / 技术报告 / Demo 页里都没有这一类),
它只能**克隆你给的一段音频**。"用文字描述一个不存在的音色"在本地**做不到**。

你现在的处境正是这一条:本机 `voices/` 里只有一个 `测试参考音频.mp3`,
5 个角色一个音色都没有 ⇒ 本地那条路**卡在第一块砖上**。

## 5. 解法:声音设计(voice design)

**它做的事正好补上那个缺口**:给一段**文字描述**,它给你一个**音色**,
而且**返回预览音频**。那段预览音频就是 IndexTTS 要的参考音频。
——"先弄到一段音频再克隆"(§5 那张表的替代方案①/②)从此有了**不需要自己录音**的做法。

四个选项(按"跟你现有条件有多贴"排):

### A. 阿里云百炼 · Qwen3-TTS 声音设计 ⭐ 推荐

来源:[声音设计官方文档](https://help.aliyun.com/zh/model-studio/qwen-tts-voice-design)。

- 模型:`qwen3-tts-vd-2026-01-26`(北京 / 新加坡两地域都有);实时版 `qwen3-tts-vd-realtime-*`。
- 描述(`voice_prompt`)**≤ 2048 字符**,只支持中文/英文 —— 中文写角色描述完全够用。
- **返回 `preview_audio`(base64)**,官方示例直接 `base64.b64decode` 存成 `preview_audio.wav`
  —— 这就是 IndexTTS 的参考音频。
- 计费:**0.2 元/个**音色;**开通后 90 天内前 10 次免费**(仅北京地域,创建失败不占次数)。
  ⇒ 造 4 个音色 **¥0.8 或免费**。
- 能力依据:Qwen 官方博客称 Qwen3-TTS-VoiceDesign 在 InstructTTS-Eval 上
  **指令跟随与表现力均超过 MiniMax 的闭源音色设计**([Qwen3-TTS 开源公告](https://qwen.ai/blog?id=qwen3tts-0115))。

### B. 阿里云百炼 · CosyVoice 声音设计

- 模型:`cosyvoice-v3.5-plus` / `v3.5-flash` / `v3-plus` / `v3-flash`(**仅北京地域**)。
- 描述 ≤ **500 字符**,参数名是 `voice_prompt`,接口是 `voice-enrollment`。
- 计费:**创建音色免费**。
- 描述上限比 A 小,但**免费**且中文调得很稳(CosyVoice 一路就是中文强项)。

### C. Qwen3-TTS 开源了 —— 全免费、可本地

- **Qwen3-TTS 全家已开源**(1.7B / 0.6B,含 `VoiceDesign`、`CustomVoice`、`Base`),
  GitHub `QwenLM/Qwen3-TTS`、HuggingFace 有权重,10 种语言含中文
  ([公告](https://qwen.ai/blog?id=qwen3tts-0115))。
- 你**本来就在本机跑 IndexTTS 2.5**(有 GPU),再挂一个 1.7B 的声音设计模型是同一档投入。
- **好处**:音色设计也本地化 ⇒ 一次性成本 **¥0**,且不依赖任何云服务。
- **代价**:要多装一套环境(它和 IndexTTS 是两套 Python 栈)。

### D. MiniMax 音色设计

- 中文可用,一句话描述生成音色([介绍](https://zhuanlan.zhihu.com/p/1932816972745282942))。
- 闭源,能力被 C/A 官方对标过。放在这里只为"知道有这条"。

## 6. 推荐路线:一条今天就能跑的(零新代码)

**核心思路:声音设计只用一次(造参考音频),真正合成用你已经装好的本地 IndexTTS。**

```
① 百炼"声音设计" → 4 段角色描述 → 每次多生成几个,挑最好的
        ↓  存下 preview_audio(wav)
② F:\creative_app\yzy-index-tts-2.5-260824\voices\
        su_qing.wav   zhou_yang.wav   su_yang.wav   (chen_yu.wav 可选)
        ↓  文件名 = 角色 id(服务端只认 voices/ 下一层文件名)
③ galfree_voice_anchor  action:"set"  → 每个角色登记参考样本(换音色 = 设定改动)
        ↓
④ galfree_voice_batch  action:"list"  → 导出清单(谁·哪句·对话 id·目标文件名)
        ↓  本地 IndexTTS 批量跑(¥0)
⑤ galfree_voice_batch  action:"import" → 按 id 收进 game/voice/,缺/多/对不上逐条报
```

**为什么这条路最顺**:

- **零新代码**:④⑤ 就是 T29 已交付的"批量清单";③ 就是 T32 的声音锚;
  IndexTTS 适配器也早就交付了。**不需要给百炼写新适配器**。
- **一致性有机制**:音色 = 参考音频文件的字节内容(同路径 ⇒ 同 cache ⇒ 同一把嗓子)。
  设计阶段怎么随机都无所谓,**一旦定下那个 wav 文件就锁死了**。
- **成本**:一次性 ¥0–1(造音色),之后每行 ¥0。
- **闭环在本地**:千行台词的批量合成不占网、不计费、可反复重跑。

**另一条路(要知道,但不推荐先走)**:直接用百炼 Qwen-TTS/CosyVoice **合成全部台词**。
台词质量可能更好(它自带情感/风格控制),但**插件现在没有百炼的适配器**
——那是 #37 里"A. 有音色的 HTTP API"那一半的开发量。等本地方案跑通、听过效果再决定要不要补。

## 8. 注意 / 没验证的(如实列)

1. **声音设计是随机的**——官方 FAQ 原话:「相同描述文本(Prompt)设计的音色可能存在差异,
   建议多次生成后择优使用」。⇒ 每个角色**多生成几次挑一个**;
   但**定下来之后不要改文件、不要重录、不要改名**(改名 = 换音色,见既有调研 §4)。
2. **没实测过**:本文所有接口细节是**读官方文档**得到的(§5-A/B),我**没有真的调用过**
   百炼的声音设计接口,也**没在本机 IndexTTS 上试过设计出来的音色**。
   第一次真跑时,`preview_audio` 的时长/采样率是否满足 IndexTTS 的
   "≤15 秒、单人、干净"要求,要当场看。
3. **参考音频 ≤15 秒**:IndexTTS 只取前 15 秒(`infer_v2_5.py:740`,既有调研 §2.5)。
   预览音频若偏长,先剪。
4. **声音描述只支持中文/英文**(官方限制)——对本作无影响。
5. **百炼的语音合成我这边没有适配器**:本插件现有 TTS 适配器只有 IndexTTS 形状的
   `sync-http`。所以 §6 那条路刻意**绕开**了这件事;要走云端合成得先开发。
6. **夏晚那 207 行的清单口径是个真缺口**(§2 的附注):她挂着 `xia_wan` 说话人,
   会被 `galfree_voice_batch` 派生进语音清单,而她的台词**不该有声音**。
   这需要一个"这个角色不配音"的表达 —— **本票没改代码**,先记在这里。
7. **主角配不配**是设计决定,不是技术问题;上面把他列为"可选"。
8. **开源那条(C)没有验证**:Qwen3-TTS 开源是官方博客说的,权重与显存要求我没实测;
   1.7B 在你那台跑 IndexTTS 的机器上应该没问题,但**没验**。

## 9. 真跑了一遍(2026-09-19):上面 §5/§6 的实测记录

§8 里"没实测过"的几条,这一节替换成**事实**。

### 9.1 实测到的接口事实(与文档的差异要注意)

| 事实 | 说明 |
|---|---|
| **地域**:北京 vs 新加坡是两把不同的 key | 本机 `.credentials.yaml` 里的 `QWEN_API_KEY` 是**北京**的:北京 `qwen-voice-design` 通,新加坡同一把 key 回 **401 InvalidApiKey** |
| 查列表:`POST …/audio/tts/customization` + `{"model":"qwen-voice-design","input":{"action":"list"}}` | **HTTP 200**,回 `output.voice_list` / `total_count`。零成本,适合先探 key 与配额 |
| `voice-enrollment` 那个 model 名走 `action:list` 会 **400 invalid action** | 列表只有 `qwen-voice-design` 这一条路 |
| 建音色用的 `preferred_name` **可以就是角色 id** | 建出来的 id 形如 `qwen-tts-vd-su_qing-voice-20260919104744548-beb5`(带时间戳) |
| **预览音频偏短:实测只有 2.0–3.9 秒** | 低于 §6 建议的 5–15 秒。**这是这次最有用的一条教训** |
| 合成接口的音频**不是内联 base64,而是一个 URL** | `output.audio.url`(带 `expires_at`),`output.audio.data` 是空串 ⇒ **要再下载一次**。文档示例没写这一层 |
| 计费按字符 | 实测一段 78 字的样音 = `usage.characters: 78` |

### 9.2 所以实际做法(与 §6 的差别:多了一步)

预览只有 2–4 秒,直接当参考音频**偏短**。于是:

```
① 声音设计造音色      → 拿到 voice_id + 2~4 秒预览
② 用那个 voice_id 再合成一段**更长、中性**的话 → 下载 → 存成 voices/<id>.wav
        （中性很重要:IndexTTS 默认 emo_control_method=0,参考音频的情绪会渗进每一句）
③ 预览留在 voices/previews/（服务端只 listdir 一层,看不见子目录,不会污染音色库）
```

### 9.4 一个**被实测证实**的缺口(§8 那条现在有证据了)

跑完四人的档案,`galfree_voice_anchor` 的板子说 **"还差 1 个角色没嗓子"** ——
那一个是 **夏晚**,而她是**设定上不该有语音**的(选择性失语,台词是笔记本上的字)。

也就是说,现在板子把**"设计上不配音"**与**"还没配音色"**混成了一件事(都会显示成"没嗓子")。
同类问题还有一处:`galfree_voice_batch` 的清单是**按"谁说了话"派生的,不区分"这句要不要出声"**,
所以本作的 3,115 行**全在清单里** —— 其中 1,958 行是旁白、207 行是夏晚的"字"。
把这份清单直接交给本地 TTS,它会**连旁白和夏晚一起念**。

要表达的是两个不同的概念(建议做成一件事):

- **非配音角色(unvoiced character)**:这个角色的台词**不出声**(夏晚);
- **旁白要不要配音**:那是**整部的风格决定**(全配音 VN / 只配角色),不是某个角色的属性。

这两条都是**创作决定**,得由人拍板 —— 本票没改代码。

## 10. 便宜的云端 TTS:比过价了(2026-09-19)

问的是"便宜的云端 TTS"。先把量摆出来:**本作要配的角色台词 13,680 字符(1.368 万字符)**。
在这个量级上,各家总价都在**几块钱以内** —— 所以"便宜"其实不是筛选条件,
真正的差别是**要不要另开账号**、**音色是不是你已设计的那 4 个**、**插件接不接得上**。

### 10.1 报价(按本作 1.368 万字符算)

| 方案 | 单价 | 整部戏 | 要不要新账号 | 能沿用刚设计的 4 个音色吗 |
|---|---|---|---|---|

### 11.2 一条**必须**遵守的硬事实:后缀只能是 `.ogg`

模板写死 `define config.auto_voice = "voice/{id}.ogg"`,而引擎那条路是
`renpy.loadable(fn, directory="audio")` → `loadable_core` → `transfn()`
→ **对精确路径做 `os.path.isfile`**(实测 SDK `renpy/loader.py:753/715/782`
与 `renpy/common/00voice.rpy:372`)。

⇒ **`voice/<id>.mp3` 是找不到的** —— 后缀必须逐字对上。
百炼回的是 wav,所以那条路里叫了一次 **ffmpeg 转 ogg(vorbis)**。

  --project D:/GALGAME/before_the_rain \

### 11.4 顺手暴露的两个建模缺口(值得单独一票)

1. **登记簿没有"云端 voice_id"这个字段**。`voiceProfile` 是 **IndexTTS 形状**的:
   `sample`(服务端音色库**文件名**)+ `speaker`(LoRA 名)+ `emotion`。
   换到任何一家云端 TTS,它要的是一个 **voice_id** —— 现在只能塞进 `voiceProfile.note`,
   由脚本正则取(`/voice_id\s+([A-Za-z0-9_-]+)/`)。要正经支持云端渠道,
   这条档案得能表达"**属于哪条渠道 + 那个渠道里的 id 是什么**"(ADR-0012 的三条渠道思路是对的,
   只是档案的形状还是单一渠道的)。
2. **"不配音的角色"没有表达方式**(§9.4 第二条)。这次靠**命令行参数**绕过去了
   (`--characters su_qing,xia_wan`),但板子本身仍然分不清"设计上不配"与"还没配"。

## 12. 配完了却**听不见**(2026-09-19 · 已修)

作者试玩后反馈"听不到语音"。655 个文件一个不差,却一句都不响。查出来**两个前提都没落地**,
而且**缺任何一个都是静默无声**(引擎不报错、试玩技术上也照过 —— 所以单看板子是发现不了的):

1. **项目里没有 `config.auto_voice`**:模板写这一行,但这项目建得比那行早 ⇒
   **老项目永远缺**(同 `build.name` / 界面补丁)。
2. **剧本里一句显式 `id` 都没有**:`stampDialogueIds` **只在测试里被调用过**,
   生成那条路从来没盖章。没显式 id 时 Ren'Py 用**内容哈希**当标识符
   (`renpy/translation/__init__.py:337-357`),`auto_voice` 于是去找一个不存在的文件名。

修法见 CONTEXT.md 的 T35 那条(生成侧盖章 / `galfree_voice_wiring` / `setDialogue` 保住 id /
音频池 `unused` 排除 `voice`)。作者复玩确认**能听见了**。

**这一票最值钱的一句**:一条链路的"函数都对、守卫都绿",不等于**它被接起来了** ——
T26 的慢带验的是"盖章函数对",而没人验"生成那条路调了它"。要验的是**端到端那一次真的响了**。
