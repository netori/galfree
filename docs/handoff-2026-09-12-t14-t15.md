## 2. 本会话最大的教训(比任何一行代码都值钱)—— 验证方式

**"文件写对了 / 进程活着 / 路由返回 200"都不等于"成了"。** 这一轮我连续用这些当判据,
结果用户**重启了六次**,每次都是我漏了一层:

- 设置命名空间注册了 ≠ 设置界面存在(要客户端半自己贡献 `settings.section`);
- 界面文件写进项目了 ≠ 试玩能跑(缺 `screens.rpy` → 关窗即崩);
- 游戏进程活着 ≠ 画面对(窗口被 `windowsHide` 藏了 / 停在中菜单 / 图没加载);
- 图片文件在磁盘上 ≠ `scene bg rooftop` 能显示(Ren'Py 已关闭自动图片定义)。

**现在的规矩**(已写进 `docs/contracts/stage-zero.md`):断言要落在**用户能看见的结果**上。
慢带里那条 `src/service/ui.slow.test.ts` 就是这条规矩的产物 —— 而且**验过它会红**
(临时关掉"补界面文件",它立刻以「缺 screens.rpy」失败)。**新写的守卫也必须这样验一次**:
从没红过的守卫不算守卫。

## 3. Ren'Py 侧花了很多时间才查明的事实(照抄,别重查)

1. **没有 `screens.rpy` 的 Ren'Py 项目连关窗都做不到。** `yesno_prompt` 只在
   `renpy.has_screen("yesno_prompt")` 成立时才挂到 `layout` 上(SDK `00layout.rpy:119/131`),
   缺了就 `AttributeError: 'Layout' object has no attribute 'yesno_prompt'`。
   对工作台的含义:**试玩永远以失败收场**(游戏跑得再好,一退出就崩)。
2. **中文字体必须用项目内相对路径。** SDK 的 `gui.rpy` 钉的是 `DejaVuSans.ttf`(无中文字形)。
   写绝对路径(`C:/Windows/Fonts/msyh.ttc`)会被 Ren'Py **静默回退** —— 不报错,中文照样方块。
   我们用 SDK 自带的 `sdk-fonts/SourceHanSansLite.ttf`(思源黑体,2.77MB,开源可携带),
   **拷进项目**、按 `fonts/SourceHanSansLite.ttf` 引用。
3. **`gui.language` 没有 `"chinese"` 这个值。** 写错渲染时抛 `Exception: Unknown language`,
   把整个对话屏打崩。合法值:`unicode` / `eastasian` / `western` / `japanese-*` /
   `korean-with-spaces` / `anywhere`。
4. **现代 Ren'Py 关了自动图片定义**(`config.automatic_images = None`,见 `00obsolete.rpy`)。
   `game/images/bg-rooftop.png` **不会**自动成为图片名 `bg rooftop`;要用得显式写
   `image bg rooftop = "images/bg-rooftop.png"`。缺这行画面是**灰底 + 图片名**
   (那是"找不到图"的提示,不是图坏了 —— 我为此误判过两次)。
5. **Ren'Py 默认先显示主菜单等人点击。** 想无头跑通"进入游戏"这条路,**我没走通**:
   试过 `define config.main_menu = [...]` 覆写、`_preferences.afm_enable` / `afm_time` 自动前进,
   都停在主菜单(用户脚本一行不执行,标记文件全空)。要验"玩通了",目前只能靠人点。
   `--warp <文件>:<行号>` 可以精确落到某一行(用它截图验过对话屏与中文)。
6. **`renpy.screenshot(path)` 的相对路径分支不可靠**(多次 exit 0 却无文件)。用绝对路径,
   或干脆别依赖它(我最后是靠"真启动不崩 + 人眼看"定论的)。
7. **用户那个上游是异步任务制**(见 §4),与 OpenAI 同步接口是两套协议。

## 4. 上游渠道实测(用户自己的网关)

- 端点 `https://api.seedance.nz/v1`,模型 `zhenzhen-image-g-v2.5-flare`,密钥明文在
  `~/.dsh/settings.yaml` 的 `dsh-galfree` 段(ADR-0010 的知情选择)。
- **协议不是 OpenAI 图像协议**,实测:
  - 提交 `POST {base}/image/generations`(**单数 image**;OpenAI 是复数 `images`)→ 回
    `{task_id, status:'queued'}`;
  - 轮询 `GET {base}/image/generations/{task_id}` → `data.status === 'SUCCESS'` + `data.result_url`;
  - 再取 `result_url` 拿 PNG 字节。
- 因此新增了第二种适配器 **`async-task`**(见 `src/service/images.ts` 与契约"两种上游协议"节)。
  这是 **T14 票面之外的范围扩张,当时经用户明确同意**。
- 出图真跑通过:两张图落盘(`bg-rooftop.png` 1536×864 / `alice-smile.png` 1024×1024),
  质量可用,我亲眼看过。

## 7. 本会话踩过的坑(工具/环境,不在任何仓库文件里)

- **PowerShell 拼中文会坏文件**:`'...'` 单引号里 `` `n `` 不换行、here-string 写中文变乱码
  (我因此写坏过 `vitest.slow.config.ts` 与两个探针脚本)。**写含中文的代码用 `write` 工具**,
  别用 PS 字符串拼接;读文件用 `read` 工具(控制台会把 UTF-8 显示成乱码,别被它骗)。
- `node --experimental-strip-types` **不支持 TS 参数属性**(`constructor(readonly x: string)`),
  探针脚本要用 `vitest run <file>` 跑。
- 一次性探针都放 `.scratch/`(gitignored),**跑完即删**。本会话有一次把 Ren'Py 探针的
  `shot-*.png` 写进了仓库根目录并误提交,已清掉并补进 `.gitignore`。
- **测试副本要把用户项目的 `game/saves` 与 `game/cache` 一起清掉**,否则游戏走存档恢复路径,
  测出来的不是新内容(我在这上面误判过)。
- `.rpyc` 缓存会让"改了源码"看起来没生效:**删掉 `game/cache` 与 `*.rpyc` 再跑**。
- 假夹具的失败行为要**与生产一致**(缺文件时报同一个业务码),否则测出来的不是产品行为。
