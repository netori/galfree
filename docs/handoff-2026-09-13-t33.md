# Handoff(2026-09-13 深夜)· T33 建音频任务的入口(音乐与语音共用一条)

> 写给**下一个会话的新 agent**。上一份 `docs/handoff-2026-09-13-t32.md`(语音的声音锚)
> 仍然有效;更早的几份也有效。本文件只写**它之后发生的事**,以及**下一张票**。

## 0. 一句话现状

发起人问「现在可以 galgame 制作这个 agent 模式**全自动加入音乐**了吗?」——
核完是**还不能**,卡点很具体:**没有人能"建"一条音频任务**(22 个工具里没有它;面板两张卡只有
"跑队列/重 roll";客户端那个 `createAudioTask` 方法**没有任何组件在调**)。于是开了 **#41(T33)**
并做完(五个提交,`0a537df`…`f23c161`):

| 提交 | 是什么 |
|---|---|
| `0a537df` | agent 工具 `galfree_generate_audio`(音乐与语音共用)+ **修掉接缝忽略 `run` 的那处** |
| `a49a9d8` | `galfree_audio_queue`(读/跑/重 roll)+ 面板「新建任务」表单 + 指引点名 |
| `f23c161` | 双轴审查的发现全修(用途只由路径判 / 排队数收成一处 / 成本分两个数) |

**验证**:快带 44 文件 **491 测试全绿**;`tsc --noEmit` 干净;`npm run build` 干净;
慢带 `routes.slow.test.ts`(含新增的"面板路由与工具同一份账本"一条)+ `audio.slow.test.ts` 全绿。

**现在的答案**:能了 —— agent 可以 `galfree_generate_audio` 建(可立刻跑)→ `galfree_audio_queue`
看/跑/重 roll → 产物落 `game/` → `galfree_wire_audio` 接进场景 → **人试听、盖场景戳**。
"全自动"到这一步为止:**好不好听、该配在哪一场,只有人能拍板**(ADR-0012 的闸门)。

## 1. 这一票补的两处"半成品"

1. **建任务的入口**(主要缺口):`service.createAudioTask` 一直在,但只有 HTTP 路由能调到它。
   现在两个入口:
   - agent:`galfree_generate_audio`(`output_path` / `model` / `prompt` 必填;`loop` /
     `dialogue_id` / `voice_id` / `run` 可选);
   - 面板:两张音频卡上的「新建任务」表单(模型从渠道目录里选,成本写在按钮上:
     「建并跑(1 条请求)」)。
2. **`CreateAudioTaskInput.run` 从来没被读过**(接缝那一层):面板那条路由自己补跑了一次,
   所以"面板建的会跑、工具建的只入队"。现在 `run` 只在接缝判一次,路由把标志原样递下去
   (201 = 只建了 / 200 = 已经跑过一次)。

## 2. 三条口径(改之前先读)

1. **用途只由目标路径判**(`purposeOfPath`):`game/voice/` 下 = 语音,其余 = 音乐。
   调用方**不递** `purpose`;真递了就必须与路径一致,不一致当场 `invalid-request`
   (认不出的值如 `'sfx'` 同样如实拒)——两条渠道的端点与目录不通用,写错就是真金。
2. **排队数只有一处实现**(`audio-generation.ts` 的 `countAudioTasks`):面板卡的"排队 N 条"、
   agent 报的成本、跑队列前那句"这一跑真发几条"读的是同一个函数。分叉的后果 T27 已经踩过一次
   (替另一条渠道花了钱)。
3. **成本分两个数**:`attempted`(这一下真跑过几次;0 = 只入队)与 `pending`(此刻排队中、
   跑队列会真发的条数)。`run` 缺省 true 时"这一跑"已经跑过了 —— 那时只报队列数就是空话。

## 3. 工具面现状(23 个)

音频那一段:`galfree_audio_channel`(读两条渠道配没配)→ `galfree_generate_audio`(建)→
`galfree_audio_queue`(读/跑/重 roll)→ `galfree_wire_audio`(接进场景);
语音还有 `galfree_voice_batch`(不花额度的清单那条路)与 `galfree_voice_anchor`(声音锚)。

**一条取舍**(审查提过、我保留了):`galfree_audio_queue` 一个工具三个 `action`。
理由:与 `galfree_theme` / `galfree_cover_art` 那种 `action:` 型工具同一形状,
而图像那边的"队列 + 重 roll"是两个工具(`galfree_art_queue` / `galfree_reroll_image`)。
要拆的话拆成 `galfree_audio_queue` + `galfree_reroll_audio`,但那会让音频段多一个工具名
(显式清单要跟着改),收益只是命名——**留待有人真觉得别扭时再动**。

## 4. 下一张票(候选,按优先级)

1. **真机验收 #36**(音乐上游第一次真打):现在能建、能跑、能落盘、能接线,**但没打过真的**。
   发起人那台机器上音乐渠道已配(`https://api.seedance.nz/v1`,目录里一条 `suno-generation`,
   异步任务制)。第一次真跑要一起看着:那个聚合站未必与 sunoapi 逐字同一套路径 ——
   模型目录的 `note` 支持 `submit=…;record=…;model=…` 覆盖(见 `audio-adapter-suno.ts` 文件头)。
2. **T34 候选 · 批量建语音任务 + 成本确认**:一场戏几十行台词,TTS **按行计费**,
   所以"建"这个动作本身要能**一次看清 N**(现在得一条一条建)。这是 ADR-0012 闸门原话
   ("按场景建任务 → 队列跑 → 板上「待复审」等人认可")里还没做的那半。
3. **每任务覆盖"纯音乐 / 带唱"**:现在由模型目录的 `capabilities.instrumental` 决定并直接进提交体;
   想按任务切换就得给 `AudioTask` 加一个布尔并让适配器优先读它(降级规矩照旧)。
