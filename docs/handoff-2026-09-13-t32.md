## 1. 三句硬事实(决定了整票的形状;别重查)

1. **音色只由参考样本决定** —— 同路径 ⇒ 同 speaker embedding 缓存命中 ⇒ 同一把嗓子
   (`indextts/infer_v2_5.py:344-350,725,774-780`)。它**没有**"用文字设计音色"那一类功能。
   ⇒ 一致性的答案 = **每个角色固定一段参考样本、每次都拿它去克隆**。
2. **`speaker` 不是音色** —— 它只选 LoRA 适配器目录(`app_api.py:168-183`),本机 `runs/` 是空的
   ⇒ `/speakers` 恒只有 `default` ⇒ **多角色不能靠 speaker 区分**。
3. **`audio` 才是音色** —— 参考样本**文件名**,服务端只在**它自己的 `voices/`** 里按名解析
   (`app_api.py:115,186-189`),**一层、无子目录、没有上传接口**。

## 2. 做出来的东西(按层看)

| 层 | 现在 |
|---|---|
| 登记簿 | `CharacterRecord.voiceProfile = { sample, speaker?, lang?, emotion?, note? }`;校验拦**路径**当样本(带 `/` `\` 盘符 `..` 全拒)、情感向量**恰好 8 个数**、强度 0–1 |
| 解析 | `src/service/voice-anchor.ts`:`resolveVoiceAnchor`(按登记簿 id 或说话人变量)与 `buildVoiceAnchorBoard`(整部戏的嗓子清单),**不碰磁盘/网络**,库清单由调用方传进来(`null` = 没核对过) |
| 建任务 | `createAudioTask`(voice)自动携链 → 任务上记 `voiceSample/voiceSpeaker/voiceLang/voiceEmotion/voiceId`;**没有就如实降级** `voice-anchor-missing`(而且一个请求都不发) |
| 适配器 | `speaker` 只从音频档案/模型目录来(**不再拿 `voiceId` 当 speaker**);`audio` 只从音色库文件名来(**不再兜底项目内路径**);情感按 `follow/reference/vector/text` → `emo_control_method` 0/1/2/3,**没配就不发** |
| 读音色库 | `readVoiceLibrary`(接缝)→ `POST /api/galfree/audio/voice/library` → 工具 `action:"library"`;**逐端点如实报**,`/speakers` 说明"那是 LoRA 名、不是音色" |
| 面板 | 角色视图每行一个「音色档案」按钮:样本输入 + **读音色库**(列出文件名与**服务端给出的绝对目录**)+ 情感四档 + 清掉;语音卡上"有嗓子 N / 还差谁" + 每条任务显示用的哪段参考 |
| agent | `galfree_voice_anchor`(read / set / clear / library);`galfree_wire_audio` 那一环的指引点名了它 |

**一条 API 纪律变了(改动虽小,影响面要记住)**:`POST /cast/characters/upsert` 从这一票起
**"body 里没有这个键 = 别动它"**(`voiceProfile: null` = 明确清掉)。此前是"没提就清空",
于是"改一次嗓子把参考链冲掉"这类错会**静默发生**。面板/工具每个字段都是分开改的,所以这条
纪律现在是必需项,不是偏好。

## 3. 两个命名空间(最容易搞错的一点,也是这一票修掉的病根)

| | 项目内 | 服务端音色库 |

`sent === []` / 项目内路径不会被发出去)。

## 4. 下一张票(候选,按优先级)

1. **T33(最自然的一张)·「把项目里的参考音频送进服务端音色库」闭环**。
   现状的**真缺口**:服务端**没有上传接口**(只能 `os.listdir`),所以参考样本要人手动丢进
   `F:\creative_app\...\voices\`。而插件与服务**同机**(适配器已经在读服务端的绝对路径)——
   也就是说"帮人复制过去"在技术上可行,但那是**项目外的写**,必须先提 ADR 修订 + 明确点头
   (ADR-0004 只管项目内的写)。AC 草案:选定项目内一段 wav → 校验(单人/时长 ≤15 s/格式)
   → 复制进服务端 `voices/<角色id>.<ext>` → 把文件名写进音色档案 → 冲突不覆盖、逐条如实报。
   **另一条更保守的替代**:不做复制,只在面板上把"该丢进哪个目录"与"文件名要叫什么"讲清楚
   (现在已经有目录了),并把"丢完了"这件事变成一次可核对的动作。
2. **按场景批量建语音任务 + 成本预览**(ADR-0012 的闸门原话:"按场景建任务 → 队列跑 →
   板上的「待复审」等人认可";#37 的 AC 也写着"一场戏 → 建任务(逐行)")。
   现状:建任务只能一条一条(agent 得自己循环),面板上没有"这一幕要 N 条、点了就发 N 条"的入口。
   TTS **按台词行计费**,所以这个"N"必须**在点之前**看得见。
3. **#36 / #37 / #38 的真机验收**(发起人侧):真打一次音乐上游 / 真出一次语音 / 真出一张封面。
