## 1. 拆渠道这件事(为什么、怎么拆的)

**起因**:发起人看到现状说「音乐和 TTS 要分开」。查下来他指的是**实现与 ADR 不符**:
ADR-0012 的 Decision 写的是"三条线 = 图像 / 音乐 / 语音。**每条线一个独立渠道**
(独立端点 + 密钥 + 模型目录),因为它们的上游与协议不重叠",而 T27 当初做成了
"音频生成渠道(音乐 + 语音**共用**)"。

| 层 | 现在 |
|---|---|
| 设置 | `music*` / `voice*` **各四个键**(两段界面,各带自己的目录示例) |
| 错误码 | `no-music-channel` / `no-voice-channel`(按用途分:"语音配好了、音乐没配"是常态) |
| 拼渠道 | `audioChannelFromSettings(settings, purpose)` 调两次,**按用途过滤目录** |
| 跑任务 / 跑队列 | 都按 `task.purpose` 分流(两条目录**不互相兜底**;跑队列按用途建队列) |
| 面板 | **两张卡**(音乐 / 语音);语音那张带「语音批量清单」 |
| agent | `galfree_audio_channel`(两条一起报) |

**没变**:任务账本仍是**一份**(`.studio/audio-tasks.json`);出网端口仍是一份
(发一个 HTTP 请求没有两条;分两份反而会让"下载口只装配了一半"变成可能)。

**两条教训**(值得记住):
1. **"共用一条渠道"是那种会悄悄发生的偏差**:不报错、能跑通、看起来更省事,
   代价要到人换上游那天才显形。判据:渠道这一层只该问"**这条线自己的端点是什么**"。
2. **"数得准"与"跑得准"必须是同一处判断**:第一版只在面板上过滤**回执**,
   于是音乐卡写"会发出 1 条"、实际会替语音发 N 条(TTS 按台词行计费,正是最贵那条)。

**旧键的处置**:`audioBaseUrl` 一族**不再被读取、也不自动迁移**(端点原本算音乐还是语音
只有人知道);设置文档里还留着它们时,面板会**如实提示一句**(有守卫)。发起人那台机器
上从来没配过音频渠道,所以这次没有真实迁移负担。

## 2. 音频模型目录(与图像同能力)

- **后端** `src/service/audio-discovery.ts`:拉 `/models` → 推断**能力与协议** → 标"待确认"。
  音乐默认**异步**(聚合站多为提交→轮询)、语音默认**同步**(本机服务一次 POST);
  认不出来的只许最基础那件事并标 `needsConfirmation`;
  **认错用途比认不出更坏** —— 音乐家族的 id 落在语音渠道上时退回保守默认并说明为什么。
  已知家族:Suno 类 / MusicGen 类 / MiniMax 音乐 / IndexTTS / GPT-SoVITS / fish-speech /
  按 voice-id 的 TTS(注意:`voiceId` 与 `voiceCloning` 是**两件事**,能力表上分开)。
- **路由** `POST /audio/channel/models`(与图像那条**共用同一个出网端口**,按 `purpose` 分流)。
- **面板** `src/client/audio-model-picker.tsx` + `audio-catalog.ts`(纯函数,可守卫):
  两条渠道各有「获取模型」+「手动添加」+ 每条勾能力;原来的 textarea 降级成
  「高级:直接看/改目录 JSON(排查用)」。目录 JSON **一定带 `purpose`**
  (少了它那条模型会在拼渠道时被静默滤掉)。
- **本机 TTS 服务没有 `/models`**(IndexTTS 那类只有 `/health` `/speakers` `/voices`)——
  接缝会如实说清并**指路手动添加**。那不是故障,是这条路在这类服务上不存在。

## 3. ⚠️ 下一张票(发起人点名问的,还没做)

**「IndexTTS 2.5 没有设计音色的功能,该如何保持声音一致性?」**

我(上一个 agent)已经查到的**硬事实**与**真缺口**:

1. **IndexTTS 2.5 是零样本克隆**:一段参考音频就能克隆音色;官方也支持用一段
   **情感参考音频**控制情绪(见 [GitHub](https://github.com/index-tts/index-tts)、
   [技术报告](https://arxiv.org/html/2601.03888v2))。它**没有**"用文字描述设计一个音色"
   那一类功能(那是 ElevenLabs voice design 那一派)。
   → **所以"一致性"的答案不是音色设计,而是"把每个角色的参考音频固定下来、每次都拿它去克隆"。**
2. **真缺口(实测代码,不是猜)**:`src/service/audio-adapter-indextts.ts` 里
   - `audio` 字段现在取 `options.audio`(模型目录 `note` 里那条**全局默认**)或
     `task.referenceAudio[0].path` —— 而后者是**项目内相对路径**(`game/voice/...`),
     服务端要的是**它自己音频库里的文件名**,这两者根本不是一回事(写错了会被服务端拒);
   - 语音任务真正携带参考音频的那条路(`createAudioTask` 的 `referenceAudio`)、
     以及登记簿里的**音色档案**,目前**没有系统化的接线** —— 也就是说
     "小棠这个角色用哪段参考音频"这件事,现在只能靠模型目录里那条全局 `note`。
   → **这就是下一张票要补的**:把"角色的声音锚"变成登记簿里的一条(参考音频 + 可选的
     情感参考),让每条语音任务自动携链(与图像那条**参考链**同一个形状:`requiresCharacters`
     → 登记簿 → 建任务时自动带上)。这正是 ADR-0012 那句"**语音用同一张簿的音色档案**
     (音色 id + 参考样本),跨场同角色同一把嗓子"的落地。
3. **一份调研报告正在生成**:`docs/research-indextts-voice.md`(由一个后台 agent 写,
   内容是**本机那份整合包 `app_api.py` 的真实参数表**(找不找得到都会如实说)+
   官方能力边界 + "同一角色一致"的具体做法 + 多角色怎么分)。
   **新会话开工前先读它**;如果它还没写完,就先自己按上面第 1/2 条往下做
   —— 那两条已经足以定一张票。

**建议的开票标题**:`T32 · 语音的「声音锚」:每个角色一份参考音频(登记簿 + 自动携链)`,
AC 大致是:登记簿能记角色的音色档案(参考音频路径 + 可选情感参考);建语音任务时**自动**
带上它(没有就如实降级并说明);`/speakers` 与 `/voices` 能被读进候选;面板能看出
"这个角色用的是哪段参考";跨场/跨批次同角色**同一把嗓子**(守卫:两次任务的请求体里
`audio` 相同)。
