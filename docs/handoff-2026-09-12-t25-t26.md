## 3. T26(#34)交付了什么 —— 语音有地方挂了

**核心是一条反直觉的 SDK 事实**(别重查):Ren'Py 的 `config.auto_voice = "voice/{id}.ogg"`
按**对话标识符**找文件,而不给显式 id 时那个标识符是**内容哈希**
(`renpy/translation/__init__.py:337-357` 的 `md5(say 的代码)[:8]`)——
**改一个字,那一句的语音文件就找不到了**。而本产品逐场重生成是常规动作。
显式 `id <name>` 子句(`renpy/parser.py:1491`)给出的标识符**与内容无关**,所以锚必须是它。

交付物:

- **`src/service/dialogue-id.ts`**:id 的取名规则(照抄引擎的 `l.name`)、行尾子句的取/剥/
  判坏、`dialogueIdFor(label, n)`、**`stampDialogueIds(source, label)`**(给一场戏的对白
  按序号盖章,**幂等**,只盖场景体那一层 —— 块构造里的行不碰)。
- **解析器**:对白语句多了 `id` 字段;行尾 `id <name>` 进子集(不是"扩到子集外");
  两种子句顺序(`id` 在 `with` 前后)都认;名字不合规则 / 同一场重名 = **error**。
- **指纹**:`sceneFingerprint` 剔掉行尾 id 子句再算(`sceneTextForFingerprint`,与解析器同源)
  —— **id 是制作信息,不是叙述内容**(ADR-0003/0009);不剔的话每生成一次语音都要人重盖一遍戳。
- **模板**:`options.rpy` 写死 `config.auto_voice = "voice/{id}.ogg"`。

**真引擎验过三件**(`dialogue-id.slow.test.ts` + 一次性探针,命令可复用):

1. `renpy.exe <项目> lint` 对盖了 id 的剧本**干净**;
2. `renpy.exe <项目> dialogue None`(launcher 的「Extract Dialogue」命令行形态,**不需要显示**)
   导出的标识符**就是我们盖的** `start_0000/0001/0002`,**不是** `start_e49b1e45` 那种哈希;
3. **缺语音文件不崩**:真起一次游戏(退出码 0、无 traceback)—— 引擎那一步是 `renpy.loadable`,
   找不到就静默跳过。

## 4. 一个仍然**没验**的点(别当成已验证)

`config.auto_voice` 在**运行时**真的把 `voice/<id>.ogg` 播出来了没有 —— 我只验到"文件被认、
不崩",**没有验"它响了"**。那条要一条真跑 + 断言 `_get_voice_info().filename` 的守卫。
踩过的坑:**Ren'Py 的测试框架不会自己推进对白**(`renpy.exe <项目> test` 会挂住),
所以别指望 `testcase` 替你走完剧本;要么用 `config.start_callbacks` 之类的探针 + 短超时,
要么把这条留给"起真窗口、人验收"。

## 5. 本轮踩过的坑(都值得记住)

1. **"空过"的守卫**:我第一版那条"带 id 的对白能解析出 id"的测试**通过了 —— 而它是假的**:
   整行被当成"无法解析"跳过了,`id` 自然是 null,断言却只查了 `id`。
   发现它靠的是**另一条**测试红了(重复 id 那条)。**教训**:断言"解析出了什么"时,
   必须连**条数**一起断言(`expect(found).toHaveLength(1)`),否则"整行没解析出来"会伪装成通过。
2. **子句顺序**:`e "文本" id ch1 with dissolve` 这种形态,如果剥离正则不准,
   会把 `ch1 with dissolve` 当成名字 → 整行解析不出来。引擎的 `finish_say` 是个**循环**,
   子句顺序自由(`parser.py:1479-1493`),剥离时必须允许"名字后面还跟着 `with <词>`"。
3. **真进程量不出来的东西就抽成纯函数**:T24 那次是 `waitForExit`((Windows 上 `kill()` 一定
   能杀掉替身,所以"没停"那条路在真进程上量不出来);这次是 `stampDialogueIds`
   (`Matter` 同理:幂等与"块里的不碰"直接喂字符串验)。
