## 3. 本会话最大的收获:慢带抓出了一个**真模板缺陷**

T18 的 AC3(产物主程序可启动)第一次跑就红了。**连查两轮**,两条都是产品级缺陷:

**① 包名是空的。** 现场:

```
[dir] -pc
  .exe          ← 主程序名是空的
```

**原因**:Ren'Py 的 `build.name` 缺省是 `None` → `directory_name`/`executable_name` 全空 →
包名 `-pc.zip`、主程序 `.exe`(引擎源码 `renpy/common/00build.rpy`)。
模板从来没声明 `build.name`,所以**所有**从我们模板建的项目打出来的包都是这个鬼样子 ——
而"构建退出码 0"永远发现不了它。
**修法**:模板 `options.rpy` 加 `define build.name = "<项目名>"`;`publishReadiness` 增加
`build-identity-missing` 阻塞项;慢带断言"包名与主程序名里必须有项目名"。

**② 打出来的游戏启动即崩。** 现场:`ModuleNotFoundError: No module named 'gui7'`
(`game/guisupport.rpy`)。模板从 SDK 拷的那份 `guisupport.rpy` 里有一段会 import **gui7**
(它只住在 `<sdk>/launcher/game/`)来生成界面图 —— 而发行版里没有 SDK。
**修法**:界面补丁里 `build.classify("game/guisupport.rpy"/".rpyc", None)` 发行版排除它,
`gui.scale` 由补丁自带。两个附带结论(**都踩过**):
**只排 `.rpy` 等于没排**(跑的是编译出来的 `.rpyc`);**别用"项目里放个空壳 gui7"这条歪路**
(Ren'Py 的导入钩子优先解析 `game/` 下的模块,空壳把**真的 gui7 也挡住**了,
于是"在 SDK 里跑"那条路上的界面图生成同样挂掉)。

**③ 顺带**:界面图(`game/gui/*.png`)是 Ren'Py **首次运行时**生成进项目的(靠的正是上面那段
gui7 代码),所以发布前置新增 `gui-images-missing`:**先跑一次试玩再发布**。

这条经验值得记住:**能红的端到端守卫比任何阅读都值钱** —— T18 的慢带一次抓出两个
"构建成功但产品是坏的"缺陷。
