## 3. 本会话踩过/查明的坑(不在任何仓库文件里)

- **`editScene` 的纯函数抛错原本会变 500**:`applySceneEdit` 的"行号越界/锚点找不到/play 没给文件"
  是**请求方的错**,现在统一翻成 `invalid-edit` / `invalid-audio`(400)。路由的错误码级联
  在 `src/routes.ts` 末尾那串三元里 —— **新加错误码必须同时登记进去**,否则静默落 500
  (T16 就栽过一次,双轴审查抓到的)。
- **`gh issue close` 没有 `--body-file`**:要留证据先 `gh issue comment --body-file`,再 `close`;
  或者 commit message 里写 `Closes #n`(push 到 main 会自动关)—— 本次两种都用上了。
- **PowerShell 里 `git push` 会把进度写到 stderr**,被 harness 当成 `[exit code: 1]` 报出来;
  看输出里有没有 `xxx..yyy  main -> main` 即可,别被吓到。
- **写 `edit` 时 old_string 末尾多带一个换行**,会把下一行的缩进吃掉(本次在 routes.ts /
  scene-workbench.tsx 各踩一次,审查抓出来的)。改完顺手 `npx tsc --noEmit` **和**扫一眼
  `git diff` 里有没有"无关行被并成一行"。
- **`computeProgress` 的 `audio` 改成必填**:不给"缺省空池"—— 空池 ≠ 没音频,
  静默绿灯比报错坏(审查的意见,已采纳)。
