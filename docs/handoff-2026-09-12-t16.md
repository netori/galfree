## 2. 本会话最大的设计决定(照抄,别重造)

**链上的图,远端拿不到 —— 所以要内联;但这个上游连内联都不收(实测)。**

登记簿的参考图是**项目内的文件**(`game/images/x.png`),而 `image_url` 要的是可取的地址。
所以发送前经 `WriteGateway.readBytes` 读字节、转 **data URL**(`dataUrlOf`),
`image_url` 收它。三条边界:

- 账本里**仍然只有路径**(引用);图片内容只在这一次出网里出现,**不落 `.studio/`**;
- 建任务时筛"文件在不在"(不在 → `degradation.code='reference-missing'` 并列出丢了哪张);
- 跑的时候若文件中途被删 → **如实报错**,不少发一张了事("链看着生效了其实没有"是要防的假象)。

**真上游把这条推理打回来了两次**(2026-09-12 实测,用户渠道 seedance):

1. 参考图发**数组** → `400 cannot unmarshal array into Go struct field .Alias.image of type string`
   —— 那个字段是**单个字符串**。已修:模型目录可声明 `referenceField: "string"`
   (面板模型行的「参考图字段」;多张时按链上顺序取第一张并记 `reference-truncated` 降级)。
2. 改对形状后再发**内联 data URL** → `400 invalid_parameter: images must contain public HTTP(S) URLs`
   —— 它**只要公网可取的 HTTP(S) 地址**,内联字节与项目内路径都不收。

**所以对这条渠道:参考链是"发得出去、上游不收"。** 诚实的做法是**把该模型的「参考链」关掉**
(任务会在建的时候如实降级,而不是每次出图撞 400);要让链真正生效,缺的是
"公网可取的地址"那一环(上游的文件上传接口 / 用户的图床)—— **下一张票的量级**。
三条拒绝都焊成了**可执行的指引**(`protocolHint`),别再让下一个 agent 对着 400 猜。

**差分批量的顺序是派生出来的**:`sortSlotsByReference` 按"谁的产物出现在别人的参考链里"
排序(主视觉先出),**不是**"槽名里带 base 的先出"。并且**建一个跑一个** ——
差分建任务时主视觉已经落盘,链才是真的。"补全全部待填"走**同一条闸门**。
