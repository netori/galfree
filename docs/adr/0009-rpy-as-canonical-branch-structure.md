# 0009 — `.rpy` 为尊:分支图是派生视图

- **状态**: Accepted(2026-07-27,grill R4-Q2)

## Context

ADR-0003 定了磁盘项目为真相源,但富结构(分支拓扑)仍有"哪边权威"的残余张力:工作台拖拽分支的编辑体验 vs "人/agent/git 平权改文本"。备选:图为尊(`.rpy` 降格为编译产物,人肉改 `.rpy` 会被覆盖——动摇 0003);粗结构/细文本分层(永久灰区)。

## Decision

`.rpy` 是分支结构的唯一权威。分支图是从 `.rpy` 解析的派生视图(缓存可弃、可全量重算);工作台的一切图编辑最终翻译成经写网关的 `.rpy` 写。

`.studio/` 铁律随本决策定稿:**只放引用与制作信息,永不复制叙述内容**;引用悬空(槽指向不存在的 label/文件)= 校验错误,进推导进度。

## Consequences

- 需要 `.rpy` 结构解析器,范围限定在**环节零方言子集**(我们生成的模板语法+常见手改),不是通用 Ren'Py parser——属环节零接缝契约。
- 解析失败(用户写了子集外的花活)时:图降级只读并如实报告,**不静默、不覆盖**。
- "外部编辑器是第一等公民"得以守住:人在 VSCode 改 `menu:`,图会变;系统永不反向覆盖手改文本。
