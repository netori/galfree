# 0012 — 生成通道:图像 / 音乐 / 语音,一条路数三条线

- **状态**:**Accepted(2026-09-12,发起人点头)** —— 同日起草、同日批准(原文为 Draft)
- **落地修订(2026-09-13)**:T27 当初把音乐与语音做成了**共用一条渠道**(四个设置键
  `audioBaseUrl` 一族),与下面 Decision 第一条不符 —— 发起人指出后拆成两条:
  `music*` / `voice*` 各四个键、错误码 `no-music-channel` / `no-voice-channel`、
  面板两张卡、跑任务**与跑队列**都按 `task.purpose` 选渠道(跑队列尤其重要:面板上
  "这一跑要花几条请求"必须就是**真会发出去的条数**,否则会替另一条渠道花钱)。
  **Decision 本身一个字没改**(它原话就是"每条线一个独立渠道"),改的是实现。
  教训写在 Consequences 第一条里。
- **旧键的处置(如实,不迁移)**:`audioBaseUrl` / `audioApiKey` / `audioChannelName` /
  `audioModels` **不再被读取**(schema 里已没有它们),也**不会**被自动迁移 —— 那个端点原本
  该算音乐还是语音,只有人知道。设置文档里若还留着它们,面板会**如实提示一句**
  (它们在 resolved 值里已经消失,所以不提示的话人只会看到"我配的渠道没了")。

## Context

v1 明确圈掉过三样东西,现在发起人要把它们加回来:

| 想要 | v1 的原文 | 出处 |
|---|---|---|
| 音乐自动生成 | "v1 的音频 = 把 BGM/SE 文件接进剧本,**没有音乐生成、没有 TTS**" | `docs/contracts/stage-zero.md`「音频接线」节 |
| 语音(TTS)自动生成 | 同上 | 同上 |
| 封面 / 主菜单 / 窗口图标 | 素材环节只有"角色登记簿驱动的立绘/背景/CG" | ADR-0005 环节 4 |

三条都撞在**同一个形状**上:把"外部模型产出的字节"变成"项目里一份能被引擎认的素材文件"。
这条形状 ADR-0010 已经在图像上解决过一次(渠道 + 任务队列 + 网关落盘 + 推导板)。

**关键区别(不能照抄图像那一套)**:图像上游有事实标准(OpenAI 兼容 `/images/generations`),
音乐与语音**没有** —— 各家都是私有协议,而且音乐那类多为"异步任务 + 轮询/回调"。

## Decision

**把 ADR-0010 的做法提升为一条通用路数,三条线各自一条渠道**:

- 三条线 = **图像 / 音乐 / 语音**。**每条线一个独立渠道**(独立端点 + 密钥 + 模型目录),
  因为它们的上游与协议**不重叠**;合成一条渠道只会得到一堆互不相干的字段。
  未来若某家同时提供多条线,作者自己在设置里填同一组端点即可 —— 结构不拦。
- **渠道 = 可配置端点 + 密钥 + 模型目录 + 适配器**。聚合站 / 自建反代 / 本地服务
  (只要肯开一个本地 HTTP 端点)**都是同一条路** —— 端点填什么就是什么,不写死厂商域名。
- **适配器按协议收,不按厂商收**:同步返回(如 MiniMax `music_generation`)、
  异步任务(提交 → 任务 id → 轮询/回调,Suno 类聚合多为此)、OpenAI 兼容(图像),
  本地 HTTP(TTS 自建)。协议参差就**如实报降级**,不静默。
- **任务队列复用图像那套**:一级对象仍是"生成任务"(目标文件 / 提示词 / 参考 / 重试历史 /
  拒收注记),产物一律**经写网关落盘**(ADR-0004)→ 进快照(ADR-0011)。
  `.studio/` 只放**引用与制作信息**,永不复制叙述内容(ADR-0003/0009)。
- **一致性锚复用登记簿**:图像继续用角色登记簿的参考链;**语音用同一张簿的音色档案**
  (音色 id + 参考样本),跨场同角色同一把嗓子。换音色 = **设定改动**,不是主观认可。
- **闸门**:按场景建任务 → 队列跑 → 板上的「待复审」等人认可。**跑之前面板上看得见
  "这一跑要花几条上游请求"**(TTS 按台词行计费)。认可戳规则不变(ADR-0008)。
- **修订 ADR-0005 环节 5 的那半句**:从"BGM/SE 接线(v1 无音乐生成、无 TTS)"改为
  "BGM/SE 接线 + 音乐生成 + 语音生成(见 ADR-0012)";环节 4 加上"封面/主菜单/窗口图标"。

## Consequences

- **"共用一条渠道"是会悄悄发生的那种偏差**(实测):T27 那句话写的是"音乐与语音**共用的**
  渠道形状",实现上就顺势做成了四个键一套端点 —— 而 Decision 第一条明写"每条线一个独立渠道"。
  它不报错、能跑通、甚至看起来更省事;代价要到人换上游那天才显形("我换了音乐那家,
  语音怎么也不出声了")。**判据**:渠道这一层只该问"这条线自己的端点是什么",
  而不是"这几条线能不能凑一个端点"。
- **成本面**(必须知情):音乐单次最贵;TTS **按台词行**计费,一场戏几十行,重 roll 一次翻倍。
  所以闸门默认是"按场景 + 待人认可",不是"定稿即连锁生成"。
- **上游不确定性**:聚合站协议变动快、厂商接口下线(实测:MiniMax 音乐接口的免费档
  2026-08-20 后下线)。因此**适配器要能报"这个模型已经不认这个形状了"**,
  而不是把上游的 4xx 翻译成"生成失败"。
- **不引入第二套真相**:音频池仍是**派生的**(文件在 `game/` 下就有它),生成只是**多一个
  往池里放文件的来源**;`playvoice`/`auto_voice` 的接线口径见 ADR-0013。
- 素材环节(ADR-0005 环节 4/5)显著变厚;**剧本与组装环节不受牵连**。
