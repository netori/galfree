# 0001 — 以 Ren'Py 作为唯一目标引擎

- **状态**: Accepted(2026-07-27)
- **决策者**: 项目发起人(经 grill-with-docs 第 1 轮确认)

## Context

插件自动化"全流程制作 galgame",需要一个稳定的成品格式作为整条 pipeline 的靶点(脚本方言、素材规格、目录结构、试玩方式都由它决定)。备选项:

1. **WebGAL** — 纯文本行式 DSL,产物是静态网页,可直接嵌在 DSH 内置浏览器里实时预览;对自动化最友好,但生态和演出上限低于 Ren'Py。
2. **Ren'Py** — 行业事实标准,Python 风格脚本(`.rpy`),生态/发行成熟;运行与打包需要本机 Ren'Py SDK(当前机器**未安装**),预览是桌面程序而非网页。
3. **自带轻量播放器** — 完全可控、可网页化,但演出效果天花板低,且放弃了行业格式。

发起人选择:成品必须能在 Ren'Py 里玩,接受工具链成本。

## Decision

以 **Ren'Py 项目**作为成品的唯一表示:流水线按 Ren'Py 的脚本与项目规范生成、校验并维护 `.rpy` 脚本与素材。

## Consequences

- 必须解决 SDK 引导:目标机器上由谁、如何安装/分发 Ren'Py SDK(遗留决策,进后续轮次)。
- **无法把游戏画面作为网页嵌入工作台实时渲染**(Ren'Py 是桌面 pygame 程序)。"实时可视化"必须落在结构化视图(剧本/分支图/素材账本)+ "一键启动 Ren'Py 试玩"之上,而非所见即所得的画面预览;若未来要求画面级 live preview,等于重新审视本 ADR。
- LLM 生成的 `.rpy` 需要验证回路(如 `renpy` 解析/lint/试玩冒烟),才能把"生成"变成可靠环节。
