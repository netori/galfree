# 0003 — 磁盘上的 Ren'Py 项目目录是唯一真相源

- **状态**: Accepted(2026-07-27,grill 第 2 轮)

## Context

工作台、DSH 端(生成流水线)、外部工具(VSCode/git)都会修改项目。权威状态放哪里决定同步模型的形态。备选:

1. 工作台内部数据库为真相,导出 `.rpy`(富结构容易,但人/外部工具被降级为二等公民)。
2. **磁盘项目目录为唯一真相**(选定):`.rpy` 与素材文件即权威;Ren'Py 不承载的制作信息放目录内 `.studio/` 元数据。
3. 双真相源 + 合并协议。

## Decision

项目 = 一个磁盘上的 Ren'Py 项目目录,是唯一真相源。所有修改(人、DSH、外部编辑器)最终都表现为对目录的写;同步 = 文件监听驱动的各侧刷新。分支图、素材槽位、制作进度等结构记录在 `.studio/` 元数据中,其与 `.rpy` 的一致性规则另行设计(引用式,悬空即校验错误——待定稿)。

## Consequences

- 冲突域从"双向合并"收缩为"写协调"(谁在何时写同一个文件),需一个写模型决策(下一轮)。
- 项目可整目录拷贝/入 git,迁移与版本管理免费获得。
- `.studio/` 与 `.rpy` 的一致性校验成为流水线的第一类需求(而非可选工具)。
- 富结构的编辑体验(拖分支节点改跳转)必须"翻译为写 `.rpy`",而不是存进数据库再说。
