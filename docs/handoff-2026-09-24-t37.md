# Handoff(2026-09-24)· T37 DSH 0.1.7 适配(插件"装不上"那次)

对着 **DSH 0.1.7-rc.2**(本机 `F:\AI\DSH`,preset 已升到 44.0.0 / `@deepseek-ai/dsh-desktop 0.1.7-rc.2`)
把 GALFree 从 0.1.5-rc.2 那一代适配过来。本文只记**为什么要这么改**与**验到了什么程度**;
逐行理由在代码注释里,契约在 `docs/contracts/stage-zero.md`。

## 1. 症状与根因

用户的原话是"**插件根本装不上/加载失败**"。查清后不是包装不上(pnpm 装得干干净净),
是**两半各断一处,而且两处都是"删掉式的变更"** —— 没有改名、没有兼容层、没有弃用告警。

| 半 | 0.1.5 用的东西 | 0.1.7 的实况 |
|---|---|---|
| Host | `ctx.settings.register(ns, schema, { base })` | **方法不存在**。`ctx.settings` 现在是 `SettingsForms`,只有 `configure/describe/update/replace/mutate/write/schema` |
| Client | `ctx.settingsScope` | asar 里 **0 命中** |
| Client | 槽位 `settings.plugin.item` / `settings.section` | asar 里 **0 命中** |
| Client | 声明 `remote.settings` 才能写 | 不再需要:共享表单**经服务提供者的 fiber** 发请求(`ui-settings` 的注释写明这是刻意的) |

Host 这一处足以解释用户看到的一切:`apply` 第一句就 `TypeError`,**fiber 激活失败 ⇒
工具面、`/api/galfree/*` 路由、流程指引一起没有** —— 面板打不开、agent 也没有 `galfree_*`。

## 2. 新模型的事实(都有出处,别照感觉写)

- **配置就是本插件那一行 Loader entry 的 config**,不再有插件自选命名空间。
  要能被设置面改的字段在 schema 上声明 **`.volatile()`**;
  Loader 把新值提交进**稳定引用**(`cordis-plugin-loader` 的 `Entry._commitVolatile` →
  `updateVolatile(ref, value)`),插件 `current()` 现读现取。
- **设置面只认 Profile 行 id**。`cordis.patch.yml` 里是 `id: galfree` / `name: 'dsh-galfree'`,
  所以 `configForms.get('galfree')` —— 传包名会一直 `unavailable`(实测的读法来自
  `ui-settings-*` 那几个随包页:`BASH_NS = "bash-sandbox"` 等,全是行 id)。
- **只有 volatile 字段进表单**:`dsh-settings` 的 `volatileForm()` 取子集,
  而 `describe()` 会**跳过没有任何 volatile 字段的 entry** ⇒ 漏一个都可能是"整页不存在"。
- **客户端页面挂在 Plugins 页的 `plugins.bundle.config`**(keyed,`key` = bundle 包名),
  注册前先问 `configForms.whileServed([...])`;旧设置页的「插件配置」标签页已整体撤掉。
- **写**:`ctx.configForms.get(id).mutate(ops, revision) → Promise<boolean>`。
  并发冲突在客户端**不是类型化异常**,就是 `false`(控制器自己重读镜像)——
  所以文案说"没被接受(可能别处刚改过)",不回显一个不存在的错误码。
- **schema 库换成 `@deepseek-ai/schemastery`**(宿主那份 fork 才有 `.volatile()`;
  peer 写 `~3.18.4`,运行时表里就有它)。**同源陷阱**:两个 schemastery 同时装会让它们各自的
  `declare global { namespace Schemastery }` **合并**,`z<Config>` 注解与整棵 schema 互不兼容
  (TS2322 报在 `meta.default` 上)—— 症状极不像"装错库",所以记在这里。
  连带:**不要再写 `: z<Config>` 注解**(volatile 字段的输入是普通值、输出是引用,两者不再相等)。

## 3. 改了什么

- `src/index.ts`:去 `ctx.settings.register`;`Config` 逐字段 `.volatile()`;新增
  `readConfig(refs)` / `ConfigValues`(`Config` 接口变成"引用形状",普通值由映射类型导出);
  `inject` 只留 `webServer`;`config ?? Config(undefined)` 让裸 cordis / 单测也拿到同一形状。
- `src/client/index.ts`:`inject = ['slots']`;`configForms` 走 **`ctx.inject` 懒装配**
  (硬 inject 缺服务会让**整个客户端半**不激活 —— 设置页画不出来不该把工作台一起拖下水)。
- `src/client/settings-card.tsx`:数据面从 `settingsScope + remote.settings` 换成
  `configForms`(`getSnapshot/subscribe/mutate`);槽位换成 `plugins.bundle.config`;
  `SETTINGS_ENTRY_ID` / `SETTINGS_BUNDLE_PACKAGE` 两个常量把"行 id ≠ 包名"这件事钉在类型面上。
- `package.json` / `tsdown.config.ts`:依赖换成 `@deepseek-ai/schemastery`(peer + dev),
  `neverBundle` 同步;devDeps 补齐 `dsh-tools` 的整套 peer 与 `dsh-llm`(否则 tsc 解析不到 `ToolSchema`)。
- 版本 **0.1.1 → 0.1.2**(`market/netori__galfree.yml` 的 tarball 指向 v0.1.2;发版步骤见 `docs/release-to-npm.md`)。

## 4. 验到了什么(以及没验到什么)

真机:建了一个 scratch profile `galfree-verify`(pnpm `link:` 本仓库),真起了一次 0.1.7 宿主。
**这套环境是临时的,验完已删除**;要复现就三步(在任何一台升到 0.1.7 的机器上):

```powershell
$env:ELECTRON_RUN_AS_NODE="1"     # 用安装里的 CLI:它跑在 asar 里,只有 Electron 的 node 读得动
$dsh = "F:\AI\DSH\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js"
$exe = "F:\AI\DSH\DeepSeek Harness.exe"
& $exe $dsh galfree-verify --from-default-profile web --dump-config   # 建 profile(打一次就退出)
& $exe $dsh plugin --profile galfree-verify add "E:\DSH_project\DSH_creator"  # 装插件(pnpm link)
& $exe $dsh galfree-verify --port 19780 --host 127.0.0.1 --no-open  # 真起宿主(后台跑)
```

起来后:`?token=` 在 stdout 里,先用它换 cookie,再走 RPC
(`POST /api/<method>`,体 `{type:'client-request', rpcId, method, payload:{args}}`)——
`settings/describe`、`settings/mutate`、`agentPresets/list` 都能问。

- `--dump-config`:`- id: galfree` 与 `preset-galgame` 两行都在位、未 disabled、
  无 incompatible/skipped 警告;
- `/api/galfree/state`、`/progress`、`/cast`、`/theme`、`/sdk` **全部 200**
  (`/progress` 回 124KB 推导板)—— 证明 `apply` 跑到尾、路由族全挂上;
- 启动载荷里 `dsh-galfree` 在 `application` 批次;`/plugins/??dsh-galfree/client.js` 200;
- `--dump-config-schema`:16 个字段**逐个**带 `"x-cordis": { "volatile": true }`
  (设置页存在的前提);
- **设置面往返**(真机,`POST /api` 的 RPC 信封 `{type:'client-request', rpcId, method, payload:{args}}`,
  先拿 `?token=` 换 cookie):
  `settings/describe` 里 **`galfree` 在列**(`autoGenerate=true` / `applies='live'` /
  16 个字段齐全);`settings/mutate` 写一次 `imageChannelName` → user 层与 revision 都对,
  再 `unset` 还原 —— 正是客户端 `ctx.configForms.get('galfree').mutate(ops, revision)` 走的那条路;
- **preset roster**:`POST /api/agentPresets/list` 返回里 `galgame`(order 5)**没有 `broken`**;
- 快带 `npm test`:**52 文件 / 552 通过 + 1 跳过**;`npm run typecheck` 干净;
  `npm ci` 在干净目录里可用(lockfile 用**不带** `--legacy-peer-deps` 的 `npm install` 重生成过 ——
  带那个旗标生成的 lockfile 会让 CI 的 `npm ci` 直接报 "out of sync")。

**没验到的(如实说)**:浏览器里那张工作台面板与设置页**真渲染成什么样**。
不过把"注册对没对"这一层补到了**产物级**:客户端的产物就是
`window.__ModuleLoader__.load({id, factory})`,所以给一个假 loader + 假 ctx 就能看它注册到哪儿 ——
`lib/client.js` 真加载、`inject = ['slots']`、三种情形全对(侧边栏 / 主面板 /
`plugins.bundle.config` keyed `dsh-galfree`;不注册回旧槽位;没有 `configForms` 时
**面板照常、设置页不注册**)。脚本 `.scratch/client-bundle-probe.cjs`(**不进仓库** ——
它是这一次的取证工具,不是守卫);同一条契约已经以 `src/client/index.test.ts` 的形式进了快带。
剩下没验的就只有"React 把这张卡画出来长什么样"。

## 5. 遗留

1. **发版**:本次只把版本号与市场条目改到 0.1.2,**没有发**(需要作者凭据/验证码)。
   发之前按 `docs/release-to-npm.md` 跑一遍,并记得 GitHub Release 资产名带版本号。
   在那之前,市场/`dsh plugin add` 装到的还是 0.1.1(那一版在 0.1.7 上装不上)。
   ⚠️ 顺带查到的:**你本机 `web` profile 里那条安装地址是死的** ——
   `~/.dsh/profiles/web/package.json` 写的是
   `releases/latest/download/dsh-galfree.tgz`,实测 **404**(0.1.1 起资产名带版本号了)。
   desktop profile 里现在没有 dsh-galfree(升级时被卸掉了)。
2. **preset(T38)已交付**:载体换成随插件 bundle 一起发的声明行;旧目录
   `~/.dsh/.agent-presets/galgame/` 可以删(没人读它了)。**同一台机器上还有三个同样死掉的
   目录**(`krea2-prompt`、`qwen-image-2-1-prompt`、`_preset`)—— 那是别的插件的,各归各家。
3. **人要做的一次**:装完重启宿主,在 GUI 里确认三件事 —— 侧边栏「GALFree 工作台」、
   Plugins 页里这个 bundle 的「配置」页(渠道都在这儿配)、新会话里的「Galgame 制作」模式。
   机器能验的到此为止(roster 无 `broken`、设置面在列、往返写能落);**"人看见了、能用了"
   这一条只有人能盖**。
4. **三个设置项在 0.1.7 上没有界面了(如实记在案,优雅降级)**:`enabled` /
   `defaultProjectsRoot` / `sdkPath` 不在这张卡上,而**别处也不写它们** ——
   旧版能改是沾了"宿主给已注册命名空间渲染通用表单"的光,0.1.7 起没有这个了
   (`autoGenerate` 只是描述字段,随包客户端没有消费者)。现在只能改 profile 的
   `cordis.patch.yml`(那一行 `id: galfree` 的 `config`)。三条都优雅降级
   (`enabled` 默认 true;新建项目表单本来就让人显式选目录;`sdkPath` 只在要覆盖钉版时才有用),
   所以是"缺口记在案"而不是"功能坏了"。**补齐 = 把它们做进那张卡**(布尔开关 + 两个路径输入),
   下一票的事 —— 现在的守卫(`settings-card.test.ts` 的 `HANDLED_ELSEWHERE`)已经把口径改正,
   不再假装"别处有界面"。
5. **⚠️ 你原来的渠道配置不在新设置里**(升级的连带,不是本次改动造成的):
   `~/.dsh/settings.yaml` 被 0.1.7 一次性导入后改名成 `settings.yaml.imported`,而导入是按
   "**段名 = entry id**"匹配的 —— 我们旧的段名是 `dsh-galfree`(旧模型的命名空间),
   行 id 是 `galfree`,**对不上**;新文件里也确实没有那一段。
   你那份 `dsh-galfree:` 段(图像渠道:`imageBaseUrl` / `imageApiKey` / `imageModels`,
   含 zhenzhen 那条 `async-task` 模型目录)**还在备份里**:
   `~/.dsh/settings.yaml.bak-vision-reasoning-20260914-171414`(第 112 行起)。
   拿它填一遍 Plugins 页那张卡即可(或让 agent 把它迁进 profile patch 的 `galfree` 行 config)。
